# live_web — 실시간 RTSP 2D→3D 검증 웹앱

실제 PTZ 카메라를 RTSP로 붙여 **라이브 프레임 한 장에 online stage(PTZ-Reloc, `--dist`)를
돌리고**, 그 프레임을 웹에서 클릭하면 **2D 픽셀 좌표와 바닥 평면 3D 월드 좌표**를 함께
보여준다. `scripts/run_ptz_reloc.py`가 디렉터리 단위 배치 처리인 것과 달리 여기서는
매칭까지 앱 안에서 수행한다(라이브 프레임에는 `pairs_matches.txt`가 없으므로).

## 빠른 시작

```bash
cd ptz_calib_dy
.venv-match/bin/python -m live_web.app          # 기본 http://<host>:8020
```

브라우저에서 접속 → **[캘리브레이션]** → **라이브 화면을 그대로 클릭**.

카메라가 움직이지 않는 한 캘리브레이션은 계속 유효하므로 정지 화면을 만들 필요가 없다.
움직였는지는 앱이 스스로 판정한다(아래 *화면 이동 감지*). 사람이 지나다니는 순간을
붙잡아 정밀하게 찍고 싶으면 **[캡처해서 고정]**으로 정지 프레임을 쓸 수 있다(돋보기도
이 모드에서 동작한다).

`.venv-match`를 쓰는 이유는 매칭에 torch(SuperPoint/SuperGlue)가 필요하기 때문이다.
이 앱을 위해 해당 venv에 `flask`, `python-dotenv`를 추가로 설치했다
(`uv pip install --python .venv-match/bin/python flask python-dotenv`).
`ptzcalib` 자체는 scipy를 쓰지 않으므로 `.venv-match`만으로 전체 파이프라인이 돈다.

RTSP 주소는 `ptz_calib_dy/.env`의 `URL`(없으면 `USER`/`PASSWORD`/`HOST`/`PORT`/`CHANNEL`)에서
읽는다 — `camera_test.py`와 같은 규칙이다.

## 화면 구성

| 요소 | 의미 |
| --- | --- |
| **LIVE / CALIBRATED FRAME** 배지 | 지금 보고 있는 것이 라이브인지 캡처해 고정한 프레임인지 |
| **화면 정지 / 화면 이동** 알약 | 캘리브레이션 시점 대비 현재 라이브 화면의 이동량 (px) |
| 클릭 마커 | 클릭 지점의 3D 좌표 라벨 |
| 초록/분홍 십자 | 서베이 점(`fit`/`holdout`)을 **현재 캘리브레이션으로 순투영**한 위치 |
| 회색 격자 | 바닥 평면 1 m 격자 (파란 굵은 선 = X=0 / Y=0 축) |
| 주황 점선 | 지평선 — 그 위를 클릭하면 바닥 평면과 만나지 않는다 |
| 돋보기 | 마우스 위치 6배 확대 + 정확한 픽셀 좌표 |
| 평면도 | X-Y 평면에서 본 카메라 · 클릭 점 · 서베이 점 |
| **PTZ 제어** 카드 | 절대 pan/tilt/zoom 이동과 프리셋 호출 — 아래 참조 |
| **재투영 오차** 카드 | 클릭한 2D 픽셀 → 예측 3D → 서베이 GT와의 오차 (m) — 아래 참조 |
| **설정** 카드의 오프라인 등급 | 레퍼런스 번들이 오프라인에서 받은 `calibration_quality` — 아래 참조 |
| 오차 선 | holdout 측정의 `GT 투영점 → 클릭점`. 선 길이가 곧 오차다 |

오버레이와 클릭은 **캘리브레이션이 지금 화면에 유효할 때만** 나온다. 라이브에서 화면이
이동하면 격자·십자가 즉시 사라지고 클릭이 막힌다 — 틀린 좌표를 조용히 내놓지 않기 위해서다.

**서베이 십자가 실제 바닥 마커 위에 얹히는지**가 캘리브레이션 품질의 즉석 눈검사다.

## 동작

1. `CameraStream` — RTSP를 계속 드레인하며 최신 프레임만 보관(버퍼 지연 방지, 자동 재접속)
2. `RelocEngine.calibrate(frame)`
   - SuperPoint 추출 (`max_keypoints 2048`, `keypoint_threshold 0.01`, resize 없음)
     + 레퍼런스와 **같은 mask**(`data/infiniq/offline/mask.png`, OSD 제거) 적용
   - 등록된 레퍼런스 20장 전체와 SuperGlue 매칭 → `conf ≥ 0.5` → RANSAC 호모그래피
     (`extract_match.filter_pair`, `min_inliers 40`)
   - inlier가 가장 많은 레퍼런스 선택 (`run_ptz_reloc.FindBestMatch`와 동일 기준)
   - `KRTOptimizer(200, 100.0, FactorType.FDist)` — 초점은 레퍼런스에서, 주점은 프레임 중앙,
     R/t/dist는 레퍼런스에서 초기화 (`run_ptz_reloc.py`와 동일)
3. `geometry.pixels_to_plane` — 클릭 픽셀을 `undistortPoints`로 펴고 광선을 만들어
   `Z = plane_z` 평면과 교차

매칭 클래스는 `scripts/extract_match.py`에서 **import**해 쓴다(복사 아님). 오프라인
파이프라인과 조용히 어긋날 수 없게 하기 위해서다.

## 화면 이동 감지

라이브 클릭이 성립하려면 "카메라가 그때 그 자세 그대로인가"를 알아야 한다. 매 프레임
SuperGlue를 돌릴 수는 없으므로, 캘리브레이션한 프레임과 현재 프레임을 480 px로 줄여
**위상 상관(`cv2.phaseCorrelate`)**으로 전역 이동량을 잰다. 국소 움직임(지나가는 사람)은
무시하고 팬/틸트/줌이 만드는 전역 변위만 잡는 성질이 여기에 딱 맞는다.

이 카메라에서 실측한 값 — 임계값 **3 px**의 근거다:

| 상황 | 측정 이동량 |
| --- | --- |
| 정지 (사람이 지나다님) | median 0.25 px, **max 0.71 px** |
| 실제 1 px 팬 | 0.74 px |
| 실제 3 px 팬 | 2.57 px |
| 실제 5 px 팬 | 4.28 px |
| 줌 ×1.02 | 1.80 px |
| 비용 | 3 ms/회 |

`response`는 어느 경우든 0.3 근처라 판별에 쓰지 않고 보고만 한다. 3 px는 노이즈 바닥
0.71 px보다 충분히 위이고, 거리 10 m·f 2850 px에서 지상 오차 약 1 cm에 해당해 기존
정확도(5~6 cm)에 묻힌다. `--drift_tolerance_px`로 조정한다.

판정은 **서버에서** 한다. `POST /api/unproject`에 `source: "live"`로 들어온 클릭은 이동이
감지되면 `409`로 거절되므로, 브라우저 상태가 늦어도 틀린 좌표가 나가지 않는다.
`source: "frozen"`은 그 프레임이 곧 캘리브레이션된 프레임이므로 항상 응답한다.

**[이동 시 자동]**(기본 켜짐)을 두면 카메라가 새 위치에 자리잡는 즉시 재캘리브레이션이
돌아 다시 클릭할 수 있게 된다. 화면은 라이브로 유지된다.

## PTZ 제어 (ONVIF)

**PTZ 제어** 카드에서 pan/tilt/zoom을 직접 입력해 절대 이동하거나, 프리셋 번호로 이동한다.
`.env`의 `ONVIF_PORT`(이 카메라는 80)로 붙는다. `SDK_PORT` 3000은 **연결을 거부**하므로
벤더 SDK 경로는 쓸 수 없고, ONVIF가 유일한 제어 경로다.

의존성은 늘리지 않았다. `live_web/ptz.py`는 `urllib` + `xml.etree`로 SOAP 봉투를 직접
만들고 WS-Security `UsernameToken`(PasswordDigest = `Base64(SHA1(nonce + created + pw))`)로
인증한다. 호출은 여섯 개뿐이라 `onvif-zeep`/`zeep`를 `.venv-match`에 더할 이유가 없었다.

### 단위 — 이 펌웨어는 두 단위를 섞어 쓴다

| 호출 | 단위 |
| --- | --- |
| `GetStatus` / `AbsoluteMove` | **ONVIF generic space** — pan·tilt `-1 ~ 1`, zoom `0 ~ 1` |
| `GetPresets` | **각도·배율** — `pan 210.9`, `tilt 9.4`, `zoom 1.7` (같은 space URI를 달고도) |

`ptz.py`가 한 곳에서 환산한다. 상수는 ONVIF 규격이 아니라 **이 카메라에서 실측**한 값이다:

```
pan_deg  = (x + 1) × 180                 x = 0.171667 → 210.9°   (프리셋 3·4와 일치)
tilt_deg = 43.5 − 46.5 × y               y = +1 → −3.0°,  y = −1 → 90.0°
zoom_x   = 1 + 22 × z                    z = 0.031818 → 1.7×     (23배 스펙과 일치)
```

pan과 zoom은 프리셋 표와 대조하면 산술로 확정되지만 tilt는 그렇지 않아, 프리셋 3·4·11
(tilt 9.4 / 16.4 / 35.0°)로 **실제로 이동시켜** 정규화값 0.733333 / 0.583011 / 0.182796을
읽었다. 세 쌍의 2점 피팅이 계수 0.05 이내로 일치해 선형임이 확인됐고, 양 끝이 −3°와 90°라는
정수로 떨어진다. 검증 결과 세 프리셋 모두 소수점 첫째 자리까지 재현된다.

UI 기본 입력은 각도·배율이고, **[정규화 단위]**를 켜면 카메라가 실제로 주고받는 값으로
바뀐다. PTZ 리드아웃을 기록하는 용도라면 후자가 원본이다.

### 프리셋

카메라는 슬롯 **256개를 전부** 보고하지만 실제로 쓸 수 있는 것은 일부다:

| 종류 | 개수 | 처리 |
| --- | --- | --- |
| `user` | 10 | 드롭다운에 표시 |
| `reserved` (토큰 65–99) | 35 | **숨김.** `open menu`, `auto scan`, `turn on ir led` 등 자세가 아니라 **벤더 명령**이다. 잘못 눌러 실행되면 안 되므로 API가 `force` 없이는 거절한다(409) |
| `empty` | 211 | 숨김. 미설정 슬롯을 펌웨어가 `1.0 / 1.0 / 1.0`으로 채운 것 |

### 이동 후

**이동하면 캘리브레이션은 무효다.** 별도 처리를 넣지 않았고 넣을 필요도 없다 — 기존
위상 상관 가드가 화면 이동을 잡아 클릭을 막고, **[이동 시 자동]**이 켜져 있으면 카메라가
멈추는 즉시 다시 푼다.

원래 자세로 되돌려도 마찬가지다. 실측한 `AbsoluteMove` 재현성은 가까운 자세로 복귀할 때는
6자리까지 정확했지만, 큰 이동 뒤 복귀에서는 정규화 `0.000166` / `0.000215`(약 0.03° / 0.01°)
어긋났다. f ≈ 2850 px에서 0.03°는 **약 1.5 px**로, 이동 판정 임계값 3 px 바로 아래다.
즉 "돌아왔으니 예전 해를 그대로 쓴다"는 성립하지 않는다.

## 재투영 오차 (holdout 2D→3D)

[재투영 오차] 카드는 **사용자가 준 2D 픽셀**을 받아 3D를 예측하고 서베이 GT와 비교한다.
`scripts/eval_own.py::holdout_2d3d`의 미터 오차와 같은 계산을, 한 클릭씩 한다.

```
사용자 클릭 (u, v)
   ↓  pixels_to_plane — 광선 ∩ Z = GT의 Z
예측 3D (X, Y, Z)
   ↓  비교
서베이 GT 3D          →  오차 (m)
```

### 왜 픽셀이 사용자로부터 와야 하는가

"holdout 점을 투영해 픽셀을 얻고 그 픽셀을 3D로 되돌려 GT와 비교"는 **항등변환**이다.
`geometry.points_to_pixels`와 `geometry.pixels_to_plane`은 정확한 역함수이고 모든 holdout 점의
Z가 역투영 평면과 같기 때문에, **화면 안에 들어오는 점은 캘리브레이션이 무엇이든 예외 없이
0.0000 m**가 나온다. 라이브 카메라에서 실측 확인:

```
POST /api/holdout  {"points": [[1082.3, 855.4], ...]}   # GT를 투영한 픽셀 그대로
  h04  err 0.0000 m  0.00 px
  h05  err 0.0000 m  0.00 px
  h06  err 0.0000 m  0.00 px
  h15  err 0.0000 m  0.00 px
```

`eval_own`도 같은 이유로 **사람이 클릭한 픽셀**(`marker.pix_raw`)을 쓴다. 사람의 클릭은
캘리브레이션과 독립된 관측이고, 이 카드가 요구하는 것도 그것이다. 따라서 이 수치는
(캘리브레이션 오차 + 클릭 정확도)다 — 십자 중심을 정확히 찍는 것이 측정의 일부다.

### 쓰는 법

1. 캘리브레이션한다. **분홍 십자**가 holdout 점을 현재 해로 순투영한 위치다.
2. [화면 클릭으로 측정]을 켜고 십자가 가리키는 **실제 바닥 지점**을 클릭한다.
   정지 프레임(`캡처해서 고정`)의 돋보기(6배)를 쓰면 픽셀을 정확히 집을 수 있다.
3. 또는 `u`, `v` 칸에 픽셀값을 직접 입력하고 [측정 추가]를 누른다(Enter도 된다).
4. 대상은 기본 `자동 (최근접)` — 예측 3D에 가장 가까운 holdout 점을 고른다. 드롭다운에는
   **지금 화면에 보이는** holdout 점만 올라오므로 직접 지정할 수도 있다.

측정은 픽셀로 보관되므로 **재캘리브레이션할 때마다 새 해로 다시 채점된다.** 카메라가
움직였다면 그 픽셀은 다른 곳을 가리키니 [지우기]로 비우고 다시 찍는다.

화면에는 `GT 투영점 → 클릭점`을 잇는 선이 그려지고, 선 길이가 곧 오차다. 색은 오차에 따라
초록/노랑/빨강이다.

### 읽는 법

| 표시 | 의미 |
| --- | --- |
| 큰 숫자 | 누적 측정의 RMSE (m). 초록 ≤ 0.12, 노랑 ≤ 0.30, 그 위는 빨강 |
| `측정 점 3 / 4` | 유효한 측정 / 전체. 지평선 위를 찍으면 무효가 된다 |
| `픽셀 오차` | GT 3D를 현재 해로 투영한 픽셀과 클릭 픽셀의 거리 (RMSE, px) |
| `X/Y 편향` | 오차의 평균 방향 — 계통 오차인지 산포인지 구분한다 |
| `h04*` | `*`는 대상을 자동으로 골랐다는 뜻 |
| `⚠` | 자동으로 고른 점이 0.30 m 넘게 떨어져 있다 — 마커 사이를 찍었거나 해가 크게 틀렸다. 대상을 직접 지정하라 |

기준선은 오프라인 georef+dist 해의 holdout 9점 **RMSE 0.078 m / 최대 0.110 m**다.
`10 px` 오클릭은 거리 5~7 m·f 2450 px에서 약 **2~3 cm**로 들어오므로, 클릭 정밀도가
이 기준선을 흐리지 않게 하려면 돋보기를 쓰는 편이 좋다.

## 오프라인 등급 (레퍼런스 번들)

**설정** 카드에 `--ref_params`가 오프라인 평가에서 받은 등급이 함께 뜬다.

```
참조 파라미터    output/output-infiniq-offline-georef-dist/offline.json
오프라인 등급    valid
오프라인 RMSE   0.078 m (기준 0.8 m)
판정 표본       9점 / 3프레임
오프라인 등록률   20/22 (90.9%)
```

`reloc.load_offline_quality()`가 `--ref_params` **바로 옆의** `eval_report.json`을 읽는다.
그 파일은 `scripts/eval_own.py --holdout`이 쓰며, 등급 정의는 `ptzcalib/quality.py`와
`EVALUATION.md` §2-6에 있다 (`valid ≤ 0.8 m < degraded ≤ 1.0 m < invalid`).

**이 등급은 레퍼런스 번들의 것이지 지금 라이브 해의 것이 아니다.** 절대 정확도는 측량점으로만
잴 수 있는데, 그 점들은 바닥 타일 격자에서 유도한 좌표라 **물리적 마커가 없어** 라이브 프레임이
스스로 다시 관측할 수 없다(§한계). 라이브 단계는 그 정확도를 **물려받을 뿐**이고, 할 수 있는 것은
거기서 벗어났는지를 감시하는 것뿐이다 — 그래서 이 숫자를 프레임 수·`factor`와 같은
**번들의 속성**으로 설정 카드에 둔다. 라이브 해의 실측치가 필요하면 아래 [재투영 오차] 카드로
직접 클릭해 재야 한다.

`eval_report.json`이 없거나 판정 이전 버전이면 `unknown — 리포트 없음` /
`unknown — 판정 이전 리포트`로 뜬다. `EVALUATION.md` §2-3 명령으로 리포트를 다시 만들면 채워진다.
`--no_georef` 번들을 가리키면 `unknown` + `측정 없음`이다 (`t = 0`이라 채점 자체가 불가).

## 2D→3D의 전제

단안 영상은 깊이를 복원할 수 없다. 3D 좌표는 **알려진 면 위에서만** 정의된다.
이 앱은 바닥 평면 `Z = plane_z`(기본 0 m, 월드는 m 단위 +X 동 / +Y 북 / +Z 상)를 쓰며,
이는 `scripts/eval_own.py::_click_ray_on_plane`이 채점하는 것과 **같은 계산**이다.
따라서 화면에 보이는 값이 곧 `eval_report.json`이 측정한 값이다.

- 바닥에 있지 않은 물체(사람 상반신, 책상 위 물건)를 클릭하면 그 광선이 **바닥에 닿는 지점**이
  나온다. 사람의 발을 클릭하면 그 사람의 바닥 위치가 된다.
- 다른 높이의 평면을 보려면 상단 `평면 Z`를 바꾼다(예: 책상 높이 0.72).
- 지평선 위를 클릭하면 `평면과 교차 없음`으로 표시된다.

## 한계

- **캘리브레이션은 그 자세에만 유효하다.** PTZ가 움직이면 위상 상관이 잡아내 클릭을
  막고(기본 3 px), [이동 시 자동]이 켜져 있으면 스스로 다시 푼다. 3 px 미만의 미세한
  흔들림은 통과하는데, 그만큼(약 1 cm)은 기존 정확도에 묻히는 크기다.
- 위상 상관은 **전역 변위**를 본다. 카메라가 전혀 안 움직였는데 화면 대부분이 바뀌는 경우
  (조명 급변, 화면을 가득 채우는 물체)는 이동으로 오판할 수 있다 — 재캘리브레이션이 한 번
  더 도는 것뿐이라 결과는 안전한 쪽으로 틀린다.
- **라이브 해에는 자동 품질 등급이 없다.** 설정 카드의 등급은 레퍼런스 번들의 것이다.
  라이브 해를 미터 단위로 채점하려면 사람이 클릭해야 하고(바로 아래 항목), 클릭 없이 얻을 수
  있는 자동 신호는 `reproj_error_px`(푸는 데 쓴 매칭으로 계산한 in-sample 값)와 inlier 수뿐이라
  그로스 실패 검출용이지 등급의 근거가 못 된다.
- **재투영 오차는 자동화할 수 없다.** 픽셀이 사용자로부터 와야 하기 때문이다(투영으로 얻으면
  항등변환). 자동 마커 검출도 불가능하다 — 서베이 좌표는 바닥 타일 격자(0.445 m 간격)에서
  유도한 값이라 **물리적 마커가 없다**: `h08`은 타일 모서리지만 `h02`·`h04`는 타일 중앙의
  무특징 지점이다. 검출할 대상 자체가 없다.
- 측정은 **픽셀**로 보관된다. 카메라가 움직인 뒤 재캘리브레이션하면 같은 픽셀이 다른 월드
  지점을 가리키므로 오차가 튄다. 그때는 [지우기]로 비우고 다시 찍어야 한다.
- 대상 자동 선택은 holdout 간격(0.445 m)의 절반 안쪽에서만 신뢰할 수 있다. 0.30 m를 넘으면
  `⚠`로 표시하고, 그 경우 대상을 직접 지정해야 한다.
- 레퍼런스 커버리지 밖(무텍스처 벽, 극단 줌)에서는 매칭 inlier가 40 미만이 되어 실패한다.
  기록된 세트 기준 70장 중 12장이 이 경우였다.
- 레퍼런스 이미지와 **해상도가 같아야** 한다(마스크 크기 검사에서 걸린다). 현재 둘 다 1920×1080.
- `dist`는 `[k1, k2, k3, p1, p2]` 순서로 저장되지만 `cv2.projectPoints`는 `[k1, k2, p1, p2, k3]`로
  읽는다. 이 데이터는 `FDist`가 **k1만** 추정하므로(자유 인덱스 10) 두 해석이 일치한다.
  k2 이상을 추정하게 바꾸면 이 부분을 먼저 정리해야 한다.
- **PTZ 이동은 캘리브레이션을 무효로 만든다.** 원래 자세로 되돌려도 `AbsoluteMove`
  재현성이 약 0.03°(≈ 1.5 px)라 예전 해를 그대로 재사용할 수 없다 — 이동 후에는 다시 푼다.
- ONVIF 각도 환산 상수는 **이 카메라(`TC-H354S SPEC:23X`)에서 실측한 값**이다. 다른 모델을
  붙이면 `ptz.py`의 `TILT_DEG_AT_UP` / `TILT_DEG_AT_DOWN` / `ZOOM_X_MAX`를 다시 재야 한다.
  정규화값(`units: "norm"`)은 모델과 무관하게 항상 정확하다.
- 프리셋 토큰 65–99는 자세가 아니라 벤더 명령이다. API가 막아 두었지만 `force`를 주면
  나가므로, 그 경로는 무엇을 실행하는지 알고 쓸 것.
- ONVIF는 **암호를 SHA-1 다이제스트로 보내지만 요청 자체는 평문 HTTP**다(포트 80). 사내
  LAN 전제이며, 그 전제가 깨지는 곳에는 두면 안 된다.
- Flask 개발 서버다. 사내 LAN 검증용이며 외부 노출 용도가 아니다.
